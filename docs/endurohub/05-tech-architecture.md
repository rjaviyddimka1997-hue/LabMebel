# 05. Техническая архитектура

## 0. Главное архитектурное решение и его обоснование

**Два контура, а не один.**

| Контур | Срок | Стек | Зачем |
|---|---|---|---|
| **Контур 1 — Telegram Mini App** | недели 1–4 (MVP), живёт всегда | React + Vite + Supabase | Нулевой CAC, аудитория уже в Telegram, проверка гипотез без установки приложения |
| **Контур 2 — нативное приложение** | месяцы 4–8 | React Native (Expo) + собственный API | Офлайн-карты, фоновая запись GPS, SOS — физически невозможны в Mini App |

**Почему не сразу натив:** установка приложения для ниши в 80 тыс. человек даёт CAC 800–1 500 ₽. Mini App — 40–120 ₽. Для проверки 17 гипотез это разница между 12 млн ₽ и 1,2 млн ₽ маркетингового бюджета.

**Почему натив всё равно неизбежен:** Telegram Mini App не имеет фоновой геолокации. Райдер кладёт телефон в карман, блокирует экран, едет 5 часов — WebView убивается ОС через 30 секунд. Запись трека и SOS в лесу — это **критичная для жизни функция**, и её нельзя строить на WebView. Любой, кто говорит обратное, не катал эндуро.

## 2. Контур 1: MVP-стек (недели 1–4)

Принцип: **ноль инфраструктурной работы, максимум продуктовой.**

| Слой | Решение | Обоснование |
|---|---|---|
| Клиент | React 18 + TypeScript + Vite + `@telegram-apps/sdk` | Мгновенная сборка, знакомый стек |
| UI | Tailwind CSS + shadcn/ui, тёмная тема | Скорость, не нужен дизайнер на старте |
| Карта | **MapLibre GL JS** + тайлы MapTiler/OSM | Открытая, без санкционных рисков, поддерживает GeoJSON-слои и кластеризацию |
| Состояние | TanStack Query + Zustand | Кеш запросов из коробки |
| Бэкенд | **Supabase** (Postgres 16 + PostGIS + Auth + Storage + Realtime + Edge Functions) | Даёт 80% бэкенда за 0 часов. PostGIS включается одной командой |
| Авторизация | Telegram `initData` → верификация HMAC в Edge Function → Supabase JWT | Один тап, без паролей |
| Бизнес-логика | Postgres RPC-функции + Edge Functions (Deno) | Сложные гео-запросы живут в БД, где им и место |
| Автоматизации | **n8n** (self-hosted) | Уведомления, постинг в чаты, парсинг GPX из каналов, алерты — без кода |
| Платежи | Telegram Stars (для подписки) + ЮKassa (для броней) | Stars дают оплату в 2 тапа внутри Telegram |
| Хостинг | Vercel (фронт) + Supabase Cloud + VPS для n8n | ~8 000 ₽/мес на старте |
| Аналитика | Yandex Metrica + собственные события в Postgres | Бесплатно, достаточно для первых 1000 |

**Критичное ограничение Supabase, которое надо знать заранее:** Row Level Security обязателен. Все таблицы с ПДн закрываются RLS-политиками, иначе анонимный ключ на клиенте = открытая база. Это первая задача спринта, а не последняя.

Пример RLS-политики (гараж виден владельцу и публично, если разрешено):
```sql
ALTER TABLE motorcycles ENABLE ROW LEVEL SECURITY;

CREATE POLICY moto_select ON motorcycles FOR SELECT
  USING (is_public = true OR user_id = auth.uid());

CREATE POLICY moto_write ON motorcycles FOR ALL
  USING (user_id = auth.uid()) WITH CHECK (user_id = auth.uid());
```

## 3. Контур 2: Backend-архитектура (месяцы 4–9)

### 3.1. Почему модульный монолит, а не микросервисы

Аргумент против микросервисов на этом этапе:
- Команда из 3–5 разработчиков. Микросервисы дадут вам распределённую монолитную систему с сетевыми задержками вместо вызовов функций.
- Нагрузка 20 тыс. MAU при сезонном пике — это ~80 RPS. Один инстанс Node справится с десятикратным запасом.
- **Выделяем отдельными сервисами только то, что имеет другой профиль нагрузки:** гео-обработку (CPU-bound, парсинг GPX и генерация тайлов) и медиа (IO-bound, транскод видео).

**Соглашения:**
- Пагинация **только курсорная** (`cursor` на base64 от `(sort_key, id)`). Offset на ленте с тысячами маршрутов — источник медленных запросов.
- Все мутации принимают заголовок `Idempotency-Key`. Обязательно для платежей и вступления в выезд.
- Гео-ответы отдаются как GeoJSON с `ST_Simplify` по уровню зума: z<10 → tolerance 0.001, z 10–13 → 0.0002, z>13 → без упрощения. Это разница между ответом 40 КБ и 4 МБ.
- Версионирование через префикс `/v1`. Ломающие изменения — только новая версия.

### 3.4. Фоновые задачи (BullMQ)

| Очередь | Задача | Расписание |
|---|---|---|
| `notifications` | Пуш «в субботу рядом 3 выезда» | Ежедневно 19:00 по локальному времени пользователя |
| `notifications` | Напоминание за 24 ч и за 2 ч до выезда | По событию |
| `maintenance` | Пересчёт напоминаний ТО при новой записи пробега | По событию |
| `geo` | Парсинг GPX, упрощение, расчёт набора высоты, обрезка приватности | По загрузке |
| `geo` | Генерация MVT-тайлов маршрутов региона | Ночью, инкрементально |
| `aggregates` | Пересчёт рейтингов, счётчиков, подтверждённой сложности | Каждые 15 мин |
| `gamification` | Проверка условий достижений | По событию завершения выезда |
| `antifraud` | Детект накрутки отзывов и фейковых организаций | Ежечасно |
| `digest` | Еженедельный дайджест региона в Telegram | Четверг 18:00 |
| `seasonal` | Зимняя реактивация: «пора готовить технику к сезону» | Март, по когортам |

### 3.5. Безопасность

| Угроза | Мера |
|---|---|
| Подделка Telegram `initData` | HMAC-SHA256 проверка по bot token, TTL 24 ч |
| Слив базы маршрутов конкурентом | Rate limit на `/routes` (60 req/min), лимит скачивания GPX, водяные знаки в треках Pro |
| Накрутка отзывов | Отзыв только от пользователя с подтверждённой бронью или участием в выезде |
| Сталкинг по геоданным | `home_point` не в API, обрезка треков, отключаемые live-координаты |
| Мошенничество с предоплатой | Escrow: деньги гиду переводятся через 24 ч после даты тура, спор — стоп-выплата |
| Инъекции в гео-параметры | Только параметризованные запросы, валидация bbox (площадь ≤ 50 000 км²) |
| DDoS на карту | CDN для тайлов, агрессивный кеш, Cloudflare/Qrator |

## 4. Frontend-архитектура

### 4.1. Веб (Next.js 15, App Router)

Роль веба: **SEO, B2B-кабинет и лендинги маршрутов.** Не «то же самое, что мобайл».

```
app/
  (public)/
    page.tsx                       # лендинг
    routes/[region]/page.tsx       # SEO: «Эндуро маршруты в Ленинградской области»
    routes/[region]/[slug]/page.tsx# SSG страница маршрута — главный источник органики
    rides/page.tsx                 # витрина выездов
    tours/page.tsx                 # витрина туров (коммерция)
    services/[region]/page.tsx     # каталог сервисов по регионам
    riders/[username]/page.tsx
  (app)/
    map/  rides/  garage/  profile/    # клиентская часть
  (business)/
    dashboard/  calendar/  bookings/  payouts/  settings/
components/
  map/          # MapLibre обёртки, слои, кластеризация, легенда уровней
  ride/  route/  garage/  org/
lib/
  api/          # типизированный клиент из OpenAPI
  geo/          # работа с GeoJSON, расчёты
```

**SEO — недооценённый канал.** Запросы «эндуро маршруты подмосковье», «где покатать эндуро спб» имеют устойчивый сезонный спрос. Каждый маршрут = SSG-страница с треком, фото, отзывами и уровнем. 3 000 маршрутов = 3 000 индексируемых страниц. Это бесплатный трафик на второй сезон.

Рендеринг:
- Лендинги и страницы маршрутов — **SSG + ISR** (revalidate 1 час).
- Витрины выездов — **SSR** (данные меняются постоянно).
- Карта и кабинет — **CSR** (интерактив).

### 4.2. Мобильное приложение (React Native + Expo)

Обоснование выбора RN против Flutter и натива:
- Переиспользование TypeScript-кода, DTO и бизнес-логики из веба — экономия ~35% времени.
- Один разработчик закрывает обе платформы. При команде в 4 человека это решающий фактор.
- Единственный реальный минус — производительность карты при рендере 500+ треков. Решается через `@maplibre/maplibre-react-native` (нативный рендер, не WebView).

```
src/
  navigation/        # Expo Router, таб-навигация
  screens/           # соответствуют структуре экранов из док. 03
  features/
    map/             # MapLibre Native, офлайн-стили
    offline/         # MBTiles регионов, предзагрузка, менеджер хранилища
    tracking/        # фоновая запись GPS
    sos/             # аварийный экран
  services/
    api/             # тот же OpenAPI-клиент
    db/              # WatermelonDB — локальная БД для офлайна
    sync/            # очередь синхронизации при возврате сети
  store/
```

**Критичные нативные модули:**

| Задача | Решение | Почему нельзя иначе |
|---|---|---|
| Фоновая запись трека | `expo-location` + `expo-task-manager`, foreground service на Android | iOS/Android убивают JS-поток при блокировке экрана |
| Офлайн-карты | `@maplibre/maplibre-react-native` + MBTiles в файловой системе | В лесу нет сети, это не опция |
| Локальная БД | WatermelonDB (SQLite) | Данные выезда должны быть доступны офлайн |
| Синхронизация | Очередь операций с идемпотентностью, разрешение конфликтов «last-write-wins» кроме ТО | Райдер вернулся из леса с 5 часами офлайн-данных |
| Энергопотребление | Адаптивная частота GPS: 1 точка / 3 сек при движении, 1 / 60 сек при стоянке | 5 часов записи не должны съесть батарею |

**Стратегия офлайна (обязательна к реализации):**
1. За 24 ч до выезда — автоматическая загрузка тайлов bbox маршрута + буфер 10 км (типично 30–80 МБ).
2. Карточка выезда, список участников, чек-лист, трек кешируются локально.
3. Все действия офлайн пишутся в очередь и отправляются при появлении сети.
4. Индикатор офлайн-режима всегда виден — пользователь должен понимать состояние.

### 4.3. Telegram Mini App (живёт параллельно навсегда)

Mini App не выбрасывается после запуска натива. Он остаётся как:
- канал первого касания (ноль трения),
- инструмент внутри партнёрских чатов,
- лёгкая версия для тех, кто не ставит приложения.

Функциональность Mini App = всё, кроме офлайна, фоновой записи и SOS. Для этих трёх — баннер «Скачай приложение, в лесу пригодится».

## 5. Инфраструктура и DevOps

| Компонент | Решение | Стоимость/мес (год 1) |
|---|---|---|
| Вычисления | Yandex Cloud, 2 × 4vCPU/8GB (API + workers) | 14 000 ₽ |
| БД | Managed PostgreSQL 16 + PostGIS, 4vCPU/16GB, реплика | 18 000 ₽ |
| Redis | Managed Redis, 2 GB | 4 500 ₽ |
| Объектное хранилище | Yandex Object Storage, ~500 ГБ медиа | 3 000 ₽ |
| CDN | Yandex CDN для медиа и тайлов | 6 000 ₽ |
| Карты | MapTiler Cloud / собственный tile-server на OSM | 0–12 000 ₽ |
| Мониторинг | Grafana Cloud free + Sentry team | 3 500 ₽ |
| CI/CD | GitHub Actions | 0 |
| **Итого** | | **~49 000–61 000 ₽/мес** |

**Собственный tile-server** (Tegola или Martin + OSM-дамп РФ) окупается при трафике от ~50 тыс. MAU. До этого дешевле платить MapTiler.

**Мониторинг — минимально обязательный набор:**
- Sentry: ошибки клиента и сервера.
- Prometheus + Grafana: p50/p95/p99 по эндпойнтам, глубина очередей BullMQ, connection pool Postgres.
- Алерты в Telegram через n8n: p95 > 800 мс, ошибки 5xx > 1%, очередь > 1000 задач, место в БД > 80%.
- **Бизнес-алерты важнее технических:** «ноль новых выездов за 24 ч в сезон» — более тревожный сигнал, чем скачок latency.

**CI/CD:**
```
push → lint + typecheck → unit-тесты → build →
  ветка main:    → staging → e2e (Playwright) → ручной approve → production (blue-green)
  ветка feature: → preview-окружение (Vercel + ветка БД в Neon/Supabase)
```

**Тестирование (прагматичный минимум для стартапа):**
| Тип | Покрытие | Что именно |
|---|---|---|
| Unit | 60% | Гео-расчёты, правила ТО, расчёт комиссии, права доступа |
| Integration | ключевые | Вступление в выезд, бронь+оплата, парсинг GPX |
| E2E | 6 сценариев | Регистрация, создание выезда, вступление, бронь тура, запись ТО, импорт GPX |
| Нагрузочные | перед сезоном | 500 RPS на `/rides` и `/routes` с реальными bbox |

Не гнаться за 90% покрытия. Гнаться за тем, чтобы **платежи и права доступа были покрыты на 100%** — остальное чинится хотфиксом, эти два — нет.

## 6. Масштабирование: что сломается и когда

| Порог | Что сломается | Решение |
|---|---|---|
| 10 тыс. маршрутов | Запрос карты по bbox отдаёт мегабайты GeoJSON | Векторные тайлы MVT вместо GeoJSON |
| 50 тыс. MAU | Одна БД не тянет чтение на пике выходного дня | Read-реплика + направление всех GET-запросов на неё |
| 100 тыс. треков | Таблица `tracks` растёт на десятки ГБ | Партиционирование по месяцам, холодные данные в S3 |
| 200 RPS на чатах | WebSocket-соединения съедают инстанс | Вынос realtime в отдельный сервис + Redis pub/sub |
| Пик сезона ×4 к среднему | Нехватка вычислений в мае | Автоскейлинг по расписанию (сезонный профиль), не по CPU |

Последний пункт специфичен именно для нашего рынка: **нагрузка предсказуема по календарю.** Масштабироваться надо к 1 мая заранее, а не реактивно.
